# 5. Behaviour rulings made during the build

Status: accepted (2026-11-21)

Small decisions that changed behaviour and are easy to get wrong when reading the code.

- **CV activation follows analysis success.** A CV becomes the active one only when its analysis succeeds. A failed upload or analysis never replaces a working CV.
- **AI cost rows outlive users.** `AiCall.userId` is `onDelete: SetNull`. The global daily AI budget sums these rows, so deleting an account (or letting a demo user expire) must not lower today's spend.
- **Demo templates carry pre-generated re-rank scores.** A new demo account starts with its matches already scored, so the first visit makes no AI call. Template data is produced by `scripts/generate-demo-template.ts` and committed as JSON.
- **Demo sessions end at `demoExpiresAt`.** Demo users last 24 h; the session stops working at that time and the ingest run deletes the user and its blobs. At most 3 demo accounts per IP hash per day, counted in a single SQL statement.
- **Failed AI work is refunded.** Usage is consumed before the call (one atomic SQL statement, so parallel requests cannot pass the limit) and refunded if the call fails after one retry. A request refused because the daily limit is already reached consumes nothing, so there is nothing to refund. Scans and empty files are rejected before any AI call and consume nothing.
- **A cancelled cover letter is spent once text has streamed.** (Reverses an earlier "abort refunds" ruling.) Cancelling before the first text delta refunds the unit; after that the unit stays consumed and no letter is saved. Otherwise opening and closing the dialog would give unlimited free Sonnet generations. Every aborted, failed or timed-out AI call records an estimated cost (input about (system + prompt) chars / 4 tokens, output about streamed chars / 4, or the full output cap for a timeout) so the global budget sees it, and every call sets `maxOutputTokens` (letters 1500, re-rank 3000, CV analysis 8000, job normalize 3000).
- **Demo content stays fresh.** Ingest never expires the jobs the demo template points at (it extends their `expiresAt` instead), and a demo user whose active CV is still the cloned template CV gets no automatic re-rank: cached scores first, vector order for the rest. Re-ranking resumes once they analyse their own CV.
- **CV uploads are capped at 4 MB.** Vercel functions accept request bodies up to 4.5 MB and the file travels in a server action, so 4 MB (with `bodySizeLimit: "5mb"`) was chosen over client-side Blob uploads. A user keeps at most 5 CVs; an unreadable upload keeps its row but its file is not stored.
- **Embeddings are lazy when the provider fails.** A paid CV analysis (or a profile edit) is saved even if embedding fails, with the embedding left NULL; `findMatches` embeds the CV when it has none. The user never pays twice for one analysis.
- **Re-rank attempts are never re-billed.** Every job sent to the re-rank is stored with `rerankedAt`, scored or not, and is not sent again for that CV (a re-analysis or profile edit clears the CV's cached matches). After an AI failure the CV's re-rank pauses for 10 minutes (`Cv.rerankFailedAt`). The matches page tells "daily limit reached" apart from "AI unavailable".
- **Tests never run `prisma migrate reset`.** Integration tests run `migrate deploy` against the `db-test` database and truncate tables before each test, behind a guard that refuses anything but the local test database (port 5433 or a name ending in `_test`).
